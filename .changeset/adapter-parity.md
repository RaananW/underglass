"@underglass/react": minor
"@underglass/vue": minor
---

The React and Vue adapters now behave alike where the two had drifted apart. React's `useSurfaceRef` no longer releases and re-enrolls its layer (with a recapture) when `decorative` changes between `undefined` and `false`, which name the same enrollment, as Vue already treated them. React's `useSurfaceRef` and `Presence` no longer write refs while rendering: a new element enrolls with the `origin` of the commit that attached it, and `onComplete` is the handler of the last commit, never of a render React discarded (a transition that suspended, for example). Vue's `Surface`, `Box` and `NativeScroll` take no `style`, as React's prop types already said: a typed template or `h()` call rejects it, a `style` passed anyway is not applied, and Vue warns about it once per component in development. Before, `Surface` dropped it without a word while `Box` and `NativeScroll` applied it; use `class`, or `layout` and `appearance`, instead. Vue's `useSurfaceRef` callback bound to a component now enrolls the component's root element (`$el`); before, it enrolled nothing and reported nothing. A ref that names no single element, or an element of another document or realm, is refused with the usual `EnrollmentError` (`foreign-element`) instead of being ignored.
