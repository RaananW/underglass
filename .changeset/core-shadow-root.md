A stage inside a shadow root now gets GPU. Before, `enable()` always stayed in DOM there with "Functional native geometry/clip probe failed interior/clipped hit testing (possibly occluded)": admission proved native hit geometry with `document.elementFromPoint`, which retargets every hit inside a shadow tree to the shadow host, so the probe was never found. Admission's three hit proofs (probe geometry, frame bounds, projective hits) now ask the output canvas's own root, its shadow root when it is in one. The `!important` pre-scan (animation ownership, and declarative transitions in ordinary DOM) now also reads the shadow root's `styleSheets` and `adoptedStyleSheets`, so a matching important transform/opacity rule there is refused like one in the document (before, it was missed and ownership was accepted). New browser test `core-shadow-root.test.mjs` (page `core-shadow-root.html`): inside an open shadow root GPU is admitted with the healthy reason, a recoloured swatch shows fresh pixels, clicks and typing reach the original button and field, and after `setTransform` the pixels and native hits move with the layer while the old place no longer hits it, at DPR 1 and 2, headless and headed.
