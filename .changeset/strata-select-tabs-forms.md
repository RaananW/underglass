Everyday forms, fourth part: the Select and the Tabs at every presentation. A Select takes `form="selector"` (the RotarySelector's dial over the Select's own native select, for up to eight short options with no optgroup; any other list is drawn as a `display`, and `data-strata-form` says which) or `form="display"` (a Display window showing the chosen option's label under the glass, between two momentary push buttons that step the native select, `aria-hidden` with `tabindex="-1"`); `multiple` is always the flush control. Tabs takes `form="rail"`: each tab a latching key on one polished plinth (the tablist), the selected key down with its LED lit, the panel the faceplate under the rail, with the WAI-ARIA Tabs pattern unchanged. `flush`, and an absent `form`, are the controls of before, pixel for pixel; no other string is a form name (on a Select it is still the native `form` owner). React, Vue and Astro render the same markup; Relief, Objects and Instrument draw the selector, the display and the push buttons as the RotarySelector, Display and PushButton do, and the rail as raised faces, keys on a slab, or one plinth part with a body and captured cap per tab and a glass LED lens that is an emitter. New plain-DOM behaviour `attachStrataSelectDisplays` (run by `attachStrata`) and `stepStrataSelect`.
